# Corrections, Withdrawals, and Retractions

Published releases are not silently overwritten.

## Report an error

Open a GitHub issue describing the affected record, source, suspected error, and supporting evidence. Use a stable record ID whenever possible.

## Correction classes

- **Metadata correction:** provenance, wording, or documentation changes that do not alter measured values.
- **Data correction:** one or more released values change after source re-checking.
- **Method correction:** a transformation, eligibility, comparability, or interpretation rule changes.
- **Withdrawal:** a source or observation is temporarily removed because validity cannot currently be established.
- **Retraction:** a release or substantial component is no longer reliable enough to remain a valid scholarly artifact.

## Release behavior

Material corrections create a new version. The changelog must identify what changed and why. Previous tagged releases remain available for audit unless legal or safety constraints require removal.

## Verification

Any correction to substantive data should be checked by someone other than the analyst who introduced the correction before the new release claims independent verification.
